# Versioning Strategy

This repository follows **Semantic Versioning (SemVer)**.

```
MAJOR.MINOR.PATCH
```

Example:

```
1.0.0
```

---

# Version Components

## Major

Major versions introduce breaking architectural changes.

Examples:

- redesigning the execution engine
- replacing the memory architecture
- changing the workflow model

Example:

```
1.0.0

↓

2.0.0
```

---

## Minor

Minor versions introduce new functionality while remaining backward compatible.

Examples:

- new workflow engine

- additional agent capabilities

- new prompt runtime features

Example:

```
1.2.0

↓

1.3.0
```

---

## Patch

Patch versions fix defects without changing system behavior.

Examples:

- documentation corrections

- metadata improvements

- schema validation fixes

Example:

```
1.3.1

↓

1.3.2
```

# Release Stages

Every version belongs to one release stage.

| Stage | Description |
|---------|-------------|
| Draft | Initial development |
| Alpha | Internal testing |
| Beta | Feature complete |
| Release Candidate | Ready for production validation |
| Stable | Production ready |
| Deprecated | Scheduled for retirement |
| Archived | Historical release |
