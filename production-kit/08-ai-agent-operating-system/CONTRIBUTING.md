# CONTRIBUTING

> Wild Story Lab OS
> Module 08 — AI Agent Operating System

Version: **1.0.0**

---

# Purpose

This document defines the contribution process for Module 08 to ensure consistency, quality, and traceability.

---

# Contribution Workflow

1. Create a feature branch.
2. Implement changes.
3. Update documentation if required.
4. Update registry entries if new assets are introduced.
5. Create or update an ADR for architectural changes.
6. Submit a Pull Request.
7. Complete review and approval before merging.

---

# Commit Convention

Examples:

```text
docs: update architecture overview
schema: add memory schema
template: improve workflow template
example: add prompt example
registry: register new agent
```

---

# Documentation Rules

- Use Markdown.
- Follow Semantic Versioning.
- Keep examples synchronized with templates.
- Link related documents where appropriate.

---

# Review Checklist

- [ ] Documentation updated
- [ ] Registry updated
- [ ] Schema validated
- [ ] Examples synchronized
- [ ] Version updated if applicable
- [ ] CHANGELOG updated

---

# Branch Strategy

- main → Stable releases
- develop → Integration
- feature/* → New work
- hotfix/* → Urgent fixes
- release/* → Release preparation

---

# Pull Request Requirements

Every Pull Request should include:

- Summary of changes
- Motivation
- Impact assessment
- Testing performed
- Related ADR (if applicable)

---

# Governance

All contributions must comply with the architecture, standards, and governance documents contained in Module 08.
